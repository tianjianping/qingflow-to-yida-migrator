# 关联组件格式转换规则（轻流 → 宜搭）

> 适用组件：轻流「关联」类组件（如 queType=25 的"选择个人客户"）→ 宜搭 AssociationFormField（关联表单/关联其他表单数据）
> 实现位置：
> - `scripts/03_transform.py`：`to_yida_association()` / `load_assoc_index()` / `find_title_queid()`
> - `scripts/02b_automap.py`：config associations 已配置的关联字段自动生成 `transform=assoc`
> - 表单配置 `config/forms/<表单>.json`：`associations` 配置段

## 1. 问题本质：轻流关联值指向"业务键"，宜搭关联值指向"实例ID"

| 维度 | 轻流（源） | 宜搭（目标） |
|---|---|---|
| 组件类型 | queType=25 等关联组件 | AssociationFormField（关联表单） |
| 值的内容 | 被关联记录的**数据ID**（=applyId，18 位数字） | 被关联记录的**宜搭实例ID**（FINST-...） |
| 值格式 | `values[0].value = "553388006941556737"` | `[{"appType", "formUuid", "formType": "receipt", "instanceId", "title", "subTitle"}]` |
| 跨系统稳定性 | 稳定（迁移前轻流侧保持不变） | 不稳定（宜搭实例ID 每次迁移一次性生成） |

经真实数据核验：轻流关联值指向的是「数据ID」（queId=-17，即 applyId），而非「编号」（queId=0）。因此转换的核心不是"格式映射"，而是**跨系统键的解析**：轻流引用什么数据ID，就必须在宜搭中找到"该数据ID对应的那一条记录"，取其 instanceId。宜搭实例ID 由 02c 阶段按「数据ID」对账生成并固化在 `<目标表单>_yida_instances.json` 的 `didToInst` 中。

### 宜搭 AssociationFormField 目标格式（官方《创建或更新表单数据格式说明》）

```json
[{
  "appType": "APP_XXXXXXXXXXXXXXXXXXXXXXXX",
  "formUuid": "FORM-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "formType": "receipt",
  "instanceId": "FINST-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "title": "示例客户姓名",
  "subTitle": ""
}]
```

## 2. 转换规则

1. **取轻流关联值**：取 `values[0].value` 作为源数据ID `src_did`。
2. **解析关联目标**：按表单 config 的 `associations` 段（`{componentId: {targetForm, titleField}}`）确定被关联表单。
3. **解析目标表单参数**：读取目标表单 config，经 `yida_context` 得到 `formUuid`、`appType`（被关联表单在哪个宜搭应用/表单，必须已配置完整，含"填入"占位符则跳过）。
4. **查 `didToInst` 映射**：加载 `<目标表单>_yida_instances.json` 的 `didToInst`（02c 阶段生成：`{轻流数据ID: 宜搭instanceId}`），`src_did` 命中则取其 instanceId。
5. **生成标题**：若配置了 `titleField`，从 `<目标表单>_raw.json` 按数据ID 取该字段值作为 `title`（如"姓名"）；未配置则 title 回退为数据ID。
6. **未命中降级**：`src_did` 不在 `didToInst`（目标记录未迁移 / 数据ID 对账失败）→ 写告警、该关联字段不写入（避免产生指向不存在实例的脏关联）。

## 3. 配置方式（表单 config 新增 associations 段）

以 `config/forms/<表单>.json` 为例：

```json
"associations": {
  "associationFormField_xxxxxxxx": {
    "targetForm": "你的被关联表单配置名",
    "titleField": "姓名"
  }
}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `associations.<componentId>` | 是 | 宜搭关联组件的 fieldId |
| `targetForm` | 是 | 被关联的表单配置名（其 `formUuid`/`appType` 自动从该表单 config + credentials 解析） |
| `titleField` | 否 | 取目标表单哪个字段值作为关联展示标题（宜搭字段名，通过目标表单 mapping 反查轻流 queId）；缺省时 title=数据ID |

配套动作（02b 自动映射已内置）：
- config 中配置了 `associations` 的关联字段，02b 自动生成 `transform=assoc`（不再标 skip）；
- 未配置的关联字段仍标 skip 并提示"需在 config associations 中配置目标表单后启用"。

## 4. 数据流与运行顺序（重要）

```
01 拉取轻流数据
02b 自动映射（引用方表单：关联字段 -> transform=assoc）
02c 拉取/对账宜搭实例（被关联表单）  ->  <被关联表单>_yida_instances.json 的 didToInst
03 转换（引用方表单）               ->  关联值 = 数据ID 查 didToInst = instanceId
04 写入宜搭
```

**必须先迁移被关联表单并生成其 `didToInst`，再转换引用方表单**，否则关联全部落为告警。

## 5. 真实数据验证

- 被关联表单 `didToInst` 含已迁移记录时，引用方命中即可写入，输出格式与官方示例一致（含正确 `title`）；
- 未命中引用产生告警（"关联的XX(数据ID=xxx)未在宜搭找到对应实例"），属**预期降级**：被关联表单尚未全量迁移；
- 待被关联表单全量迁移后重跑 `03_transform.py <引用方表单> --full`，命中数将随 `didToInst` 扩大而提升，无需改动任何代码或配置。

## 6. 边界与已知限制

- **关联的关联**：轻流若存在"引用方的引用方"（如 A→B→C），每层都需要各自的 associations 配置与目标 didToInst，目前按单层处理。
- **titleField 缺失时**：title 回退为数据ID（数字），不影响关联正确性，仅展示不友好。
- **被关联表单在其他宜搭应用**：需在其自身 config 的 `yida` 节点显式补 `appType`，否则按 credentials 默认应用解析（`yida_context` 兜底逻辑）。
- **引用未迁移记录**：不写入脏关联、仅告警，符合"宁可缺失、不可错链"原则；如确需保留原引用文本，可另行在目标表单增加"原数据ID"文本字段（本规则未做）。
- **多选关联**：轻流关联组件如允许多选（values 多行），当前取首个 value，多选场景需扩展为遍历 values 生成多个关联对象。
