## 报告安全漏洞（Reporting a Vulnerability）

本项目不存储、不中转任何用户数据或凭证，凭证由用户在本机自行配置。

如果你发现了安全漏洞（例如：凭证泄露路径、路径穿越、未授权上传、越权访问等），请按以下方式报告：

1. **不要**在公开的 Issue 中直接贴出真实的密钥、Token 或业务数据样本。
2. 通过 GitHub 的 **Security Advisory**（仓库页 -> Security -> Report a vulnerability）提交，或发送邮件到维护者邮箱（见仓库首页）。
3. 请在报告中包含：受影响版本、漏洞描述、可复现步骤、影响范围与修复建议（可选）。

我们会在 **7 个自然日**内确认，并在修复后公开发布安全公告（如需）。

## 安全设计约定

- 所有 API 凭证仅通过本地 `config/credentials.json` 或环境变量提供，代码中不出现任何硬编码密钥。
- 凭证可在部署后经网页「设置 → 凭证」页配置：服务默认仅监听 `127.0.0.1`；以非本机地址部署时**必须**设置 `MIGRATION_API_TOKEN` 作为接口认证令牌，并自动进入**脱敏模式**：
  - 凭证接口只写不回显，敏感值以掩码（首字符 + `***` + 末 4 位）展示，`?view=full` 请求被拒绝（403）；
  - 网页保存时拒绝含占位提示（如"你的/填入/xxxx"）的输入；留空 = 保持原值，仅显式 `clear` 才置空；
  - 被环境变量覆盖的字段在网页不可修改，且优先级始终高于文件值。
- 数据迁移在本机与官方 API 端点之间直连，开发方不接触、不留存任何用户数据。
- 附件上传接口强制 `X-Upload-Token` 校验、扩展名白名单、路径穿越防护。
- 禁止在 Issue / PR / Commit 中提交任何真实密钥、Token、域名或业务数据。
