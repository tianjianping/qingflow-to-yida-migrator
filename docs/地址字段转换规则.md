# 地址字段格式转换规则（轻流 → 宜搭）

> 适用组件：轻流「地址」字段（queType=21）→ 宜搭 AddressField（地址选择）
> 实现位置：`scripts/03_transform.py` 的 `to_yida_address()`（与 `extract_raw()` 的 `AddressField` 分支）

## 1. 两侧格式差异

| 维度 | 轻流（源） | 宜搭（目标） |
|---|---|---|
| 字段类型 | queType=21（地址） | AddressField（地址选择） |
| 数据结构 | `values[]` 数组，逐级一项 | 单个 JSONObject |
| 区域标识 | `otherInfo` = 6 位行政区划代码（GB/T 2260） | `regionIds[]` = 区域编码数组 |
| 区域名称 | `value` = 中文名 | `regionText[]` = `{zh_CN, en_US}` 数组 |
| 详细地址 | 最末级 `value`（无 otherInfo） | `address` 字符串 |
| 附加能力 | 无经纬度 | 可含 `longitude`/`latitude`（本规则不迁移） |

### 轻流原始结构（示例）

```json
{
  "queId": 1234567, "queTitle": "地址", "queType": 21,
  "values": [
    {"id": 1, "value": "陕西省", "otherInfo": "610000"},
    {"id": 2, "value": "汉中市", "otherInfo": "610700"},
    {"id": 3, "value": "佛坪县", "otherInfo": "610730"},
    {"id": 4, "value": "某街道某号", "otherInfo": null}
  ]
}
```

层级分布：省/市 2 级、省/市/区县 3 级、4 级（最末级为详细地址，可空）。

### 宜搭目标格式（官方《创建或更新表单数据格式说明》）

```json
{
  "address": "详细地址文本",
  "regionIds": [610000, 610700, 610730],
  "regionText": [
    {"en_US": "shan xi sheng", "zh_CN": "陕西省"},
    {"en_US": "han zhong shi", "zh_CN": "汉中市"},
    {"en_US": "fu ping xian", "zh_CN": "佛坪县"}
  ]
}
```

## 2. 转换规则

对轻流 `values[]` 按 id 顺序逐项处理：

1. **结构化层级**：`value` 非空 且 `otherInfo` 可解析为纯数字 → 视为区域层
   - `regionIds` 追加 `int(otherInfo)`
   - `regionText` 追加 `{"zh_CN": value, "en_US": <value的拼音>}`
2. **详细地址**：`value` 非空 但 `otherInfo` 为空/不可解析 → 文本片段，收集后以空格拼接进 `address`
3. **兜底（纯文本地址）**：整字段没有任何可解析代码（如轻流把文本直接存在 value 中）→ 全部文本以逗号拼接进 `address`，`regionIds`/`regionText` 留空数组，并写告警提醒人工核对（宜搭端以纯文本展示）
4. **全空**：无任何 `value` → 返回空结构，`wrap()` 阶段自动置为 None，不写入

### en_US 拼音生成

- 首选 `pypinyin`（可选依赖），`Style.NORMAL` 无调音节、空格分隔，与官方示例 `"bei jing shi"` 一致
- 未安装 pypinyin 时回退为 `en_US = zh_CN` 原文：结构完整、宜搭可正常存储展示，仅英文文案缺失

## 3. 边界情况与已验证样例

| 场景 | 输入 values | 输出 |
|---|---|---|
| 3 级省市区 | 陕/汉/佛坪 + 610000/610700/610730 | `regionIds=[610000,610700,610730]`，3 组 regionText，`address=""` |
| 2 级省市 | 陕/汉 + 610000/610700 | `regionIds=[610000,610700]`，2 组 regionText |
| 4 级带详细地址 | 省/市/县 + 代码，末级 `value="某街道某号"` | 3 组 regionIds/regionText + `address="某街道某号"` |
| 4 级空详细地址 | 末级 `value=""` | 空值被跳过，仅 3 级结构化输出 |
| 纯文本无代码 | `value="高新区科技路", otherInfo=null` | `address="高新区科技路"`，regionIds/regionText 空 + 告警 |
| 全空 | `value=""` | 返回空，最终不写入 |

真实数据验证：2 级结构与 3 级结构为主（各占比随表单业务而异），regionIds 与 regionText 层级严格一一对应，转换后 0 条告警。

## 4. 已知限制与后续建议

- **regionIds 编码一致性**：轻流 `otherInfo` 为标准 6 位 GB/T 2260 代码，与宜搭前三级编码一致，可直接使用。宜搭部分表单支持 9 位乡镇级扩展编码（如 `469023401`），轻流不含乡镇级代码，故乡镇及以下层级无法结构化，仅以 `address` 文本保存。
- **经纬度**：轻流地址组件不含经纬度数据，宜搭 `longitude`/`latitude` 字段不填。
- **en_US 依赖**：如需完整英文拼音，部署环境需 `pip install pypinyin`（见 `requirements.txt` 注释）。
- **试迁核对**：建议迁移后抽查若干条记录，在宜搭数据管理中确认地址组件按省市区正确渲染、详细地址落在"详细地址"输入框中。
